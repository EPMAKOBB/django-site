# Состояние сайта "Фрактал" для подготовки бизнес-плана

Дата среза: 2026-08-01.

Этот документ нужен как вводная записка для следующей версии Codex/ChatGPT, с которой будет составляться бизнес-план проекта. Он описывает, что представляет собой сайт сейчас, какие части уже реализованы, как им пользоваться и какие ближайшие шаги запланированы.

## 1. Краткое описание проекта

"Фрактал" - образовательный сайт и задел под EdTech-платформу для подготовки школьников к экзаменам. Центральная идея продукта: ученик не просто получает набор материалов, а решает задания, по которым система накапливает данные о прогрессе и подбирает следующие задачи под его слабые места.

Сайт совмещает две линии продукта:

- самостоятельная подготовка через экзамены, задания, персональные варианты и тренировочный режим;
- подготовка с учителем через заявки, личные кабинеты, связи "учитель - ученик", классы и выдачу вариантов.

В текущем виде это не только лендинг школы, а рабочий Django-сайт с моделями пользователей, задач, экзаменов, вариантов, попыток, рекомендаций, тренировочных сессий и курсов.

## 2. Целевая аудитория

Основные пользователи:

- школьники, которые готовятся к ЕГЭ/экзаменам самостоятельно;
- школьники, которые хотят заниматься с преподавателем;
- преподаватели, которым нужно отслеживать учеников и выдавать варианты;
- методист/администратор, который наполняет базу задач и управляет материалами.

Для бизнес-плана важно рассматривать проект как гибрид:

- B2C: ученик покупает доступ к самостоятельной подготовке или оставляет заявку на занятия;
- B2C/B2B2C: преподаватель ведет учеников через платформу;
- внутренний методический инструмент: база задач, варианты, источники, импорт и редактура материалов.

## 3. Что уже сделано

### 3.1. Публичная часть сайта

Готова новая главная страница:

- главный оффер: "Система, которая подбирает задачи под тебя";
- выбор самостоятельной подготовки по активным экзаменам;
- форма заявки на подготовку с учителем;
- блок "О проекте";
- блок "О нас";
- ссылки на Telegram, VK и YouTube;
- отзывы учеников;
- переход в личный кабинет.

Главная уже переведена на новую визуальную основу сайта. Экспериментальная страница `/home-v2/` использовалась как источник направления, но production-главная находится на `/`.

### 3.2. Заявки на обучение

Есть приложение `applications`, которое принимает заявки на обучение.

Форма собирает:

- имя контактного лица;
- имя ученика, если указано;
- класс;
- выбранные предметы;
- контактную информацию;
- тип занятия/оффер;
- статус обработки заявки.

Основной сценарий: посетитель оставляет заявку с главной страницы или через `/applications/`, после чего заявка попадает в базу и может быть обработана администратором.

### 3.3. Аккаунты и роли

Реализованы:

- регистрация и вход через единый экран `/accounts/signup/` и `/accounts/login/`;
- личный кабинет `/accounts/dashboard/`;
- роли/профили ученика, учителя и методиста;
- связь учителя и ученика через invite-коды;
- учебные классы/группы;
- присоединение к учителю или классу по ссылке;
- настройки кабинета.

В кабинете есть разделы:

- история;
- курсы;
- учительская;
- мои ученики;
- классы;
- системный журнал для staff-пользователей;
- настройки;
- методистский раздел.

### 3.4. Экзамены и страницы предметов

Есть публичные страницы экзаменов по маршруту:

- `/exams/<exam_slug>/`

На странице экзамена реализованы:

- название предмета и версии экзамена;
- прогноз баллов;
- общий прогресс;
- сильные и слабые стороны;
- блоки публичных вариантов;
- список типов заданий;
- переход к персональному варианту;
- переход в тренировочный режим.

Для неавторизованных пользователей персональная аналитика скрыта или заменена призывом войти.

### 3.5. База задач

В проекте есть развитая модель задач:

- предметы;
- версии экзаменов;
- типы заданий;
- теги;
- навыки;
- источники;
- варианты источников;
- статусы публикации задач;
- сложность;
- правильные ответы;
- схемы ответа;
- изображения и вложения;
- markdown/html/plain-рендеринг условий;
- динамические и статические задачи;
- предсгенерированные наборы данных для динамических задач.

Условия задач приводятся к единому presentation-представлению через `build_task_statement_payload()`. Это важно для качества продукта: одна и та же задача должна одинаково выглядеть в списке, варианте, решателе и тренировке.

### 3.6. Персональные варианты и решатель

Реализованы:

- шаблоны вариантов;
- публичные страницы вариантов `/variants/<slug>/`;
- назначение варианта ученику;
- старт попытки;
- сохранение, очистка и отправка ответа по задаче;
- финализация попытки;
- heartbeat и учет активной задачи;
- учет времени по задаче;
- история попыток;
- пересборка персонального варианта.

Для ученика это выглядит как сценарий "собрать персональный вариант - решить - получить результат".

### 3.7. Рекомендательная система

В проекте есть рекомендательная логика, которая учитывает прогресс пользователя и подбирает следующие задачи.

Реализованы:

- учет попыток;
- мастерство по навыкам/тегам;
- история рекомендаций;
- причины рекомендаций;
- фильтрация по версии экзамена;
- фильтрация по выбранным типам заданий в тренировке;
- пересчет состояния через management-команды.

Текущая важная бизнес-идея: сайт постепенно превращает подготовку из "решай все подряд" в адаптивную траекторию.

### 3.8. Тренировочный режим

Реализован первый рабочий тренировочный режим:

- маршрут `/exams/<exam_slug>/training/`;
- старт тренировочной сессии;
- продолжение текущей сессии;
- завершение сессии;
- выбор типов заданий перед стартом;
- рекомендованные типы по данным системы;
- выдача задачи по одной;
- проверка ответа;
- возможность повторить неверный ответ;
- явный переход к следующей рекомендованной задаче;
- история решенных шагов в сессии.

Важное текущее решение: после проверки ответа система не перекидывает ученика автоматически дальше. Ученик сам нажимает "Подобрать следующую", а при ошибке может попробовать еще раз.

Ограничение текущей версии: успешно решенные задачи пока исключаются из рекомендаций строго. Интервальное повторение и возврат решенных задач по модели забывания пока отложены.

### 3.9. Курсы

Есть приложение `courses` с моделями:

- курс;
- запись ученика на курс;
- модули курса;
- граф связей между модулями;
- карточки теории;
- элементы модуля: теория или задача;
- отметки о прохождении.

Это задел для более структурированных программ подготовки, где задания и теория связаны в учебную траекторию.

### 3.10. Администрирование и методическая работа

Для staff-пользователей есть:

- загрузка задач `/tasks/upload/`;
- редактирование задач `/tasks/redact/`;
- карта покрытия задач по источникам и типам `/tasks/variant-map/`;
- сборщик вариантов `/tasks/variant-builder/`;
- список задач `/tasks/`;
- Django admin `/admin/`;
- management-команды для импорта, посева данных, пересчета прогресса и отчетов публикации.

Отдельно документирована работа с Markdown и формулами KaTeX в `docs/markdown_math_authoring.md`.

## 4. Как можно пользоваться сайтом сейчас

### Сценарий посетителя

1. Открыть главную страницу `/`.
2. Выбрать самостоятельную подготовку по доступному экзамену или оставить заявку на занятия с учителем.
3. Если выбрана самостоятельная подготовка, перейти на страницу экзамена.
4. Зарегистрироваться или войти, чтобы получить персональный прогресс и персональные варианты.

### Сценарий ученика

1. Войти через `/accounts/login/`.
2. Открыть нужный экзамен `/exams/<exam_slug>/`.
3. Посмотреть прогресс, сильные и слабые стороны.
4. Собрать персональный вариант или открыть тренировку.
5. В тренировке выбрать типы заданий, решить задачу, получить проверку и перейти к следующей рекомендации.
6. В личном кабинете смотреть историю, курсы и назначенные варианты.

### Сценарий учителя

1. Войти в аккаунт учителя.
2. Подключить учеников через invite-коды или классы.
3. Смотреть учеников в кабинете.
4. Собирать или назначать варианты.
5. Анализировать результаты и прогресс учеников.

### Сценарий методиста/администратора

1. Войти как staff-пользователь.
2. Добавлять и редактировать задачи.
3. Настраивать предметы, экзамены, типы заданий, схемы ответов и варианты.
4. Проверять покрытие базы задач через карту вариантов.
5. Импортировать предсгенерированные пулы задач.
6. Пересчитывать состояние рекомендательной системы при необходимости.

### Локальный запуск для разработки

Базовый запуск проекта:

```bash
python manage.py migrate
python manage.py createsuperuser
python manage.py seed_ege
python manage.py collectstatic --noinput
python manage.py runserver
```

Полезные проверки:

```bash
python manage.py check
python manage.py test apps.recsys.tests.test_training_api_flow --keepdb
```

- полноценная продуктовая упаковка курсов.

## 6. Ближайшие планы

Приоритетные ближайшие работы:

1. Довести тренировочный режим до более зрелого UX:
   - обзор решенных шагов;
   - понятный экран завершенной сессии;
   - обработка случаев, когда задачи в выбранных типах закончились;
   - больше тестов на возобновление и завершение сессий.

2. Спроектировать интервальное повторение:
   - когда успешно решенная задача может вернуться;
   - как учитывать забывание;
   - нужен ли режим "повторить решенные";
   - как не портить мотивацию ученика повторными задачами.

3. Завершить унификацию задач:
   - не добавлять новых способов рендеринга условий;
   - все новые поверхности должны использовать существующий `task_statement`/`FractalTaskStatement`;
   - развить общий слой отображения ответов и feedback.

4. Продолжить редизайн:
   - solver;
   - личный кабинет;
   - кабинеты учителя и методиста;
   - финальная зачистка старых стилей.

5. Развивать курсы:
   - сделать их понятной продаваемой единицей;
   - связать теорию, задания и прогресс;
   - определить, как курс отличается от свободной тренировки.

6. Подготовить бизнес-упаковку:
   - тарифы;
   - описание ценности для ученика и родителя;
   - описание ценности для учителя;
   - план наполнения базы задач;
   - модель привлечения заявок;
   - метрики удержания и прогресса.

## 7. Что важно учесть при составлении бизнес-плана

Проект уже имеет техническую основу, но коммерческая упаковка еще не зафиксирована. Поэтому бизнес-план стоит строить не как план "создать сайт с нуля", а как план вывода существующего MVP в устойчивый образовательный продукт.

Сильные стороны:

- есть рабочий сайт, а не только идея;
- есть персонализация через задачи, прогресс и рекомендации;
- есть связка самостоятельного и преподавательского форматов;
- есть база для масштабирования контента;
- есть задел под курсы;
- есть собственная методическая и преподавательская экспертиза.

Риски и открытые вопросы:

- нужно уточнить объем и качество наполнения задачами по каждому экзамену;
- нужно определить, что именно продается: доступ к платформе, занятия, курс, гибрид;
- нужно продумать оплату и юридическую часть;
- нужно решить, какие метрики доказывают эффективность подготовки;
- нужно довести интерфейс кабинетов до коммерческого уровня;
- нужно оценить стоимость регулярного наполнения и проверки задач.

## 8. Рекомендуемый фокус бизнес-плана

Для ближайшего бизнес-плана лучше взять фокус:

"Фрактал" как платформа адаптивной подготовки к ЕГЭ с возможностью самостоятельной тренировки и сопровождения преподавателем.

Не стоит позиционировать проект только как "сайт репетиторов" или только как "банк задач". Самая сильная часть продукта - связка:

- база экзаменационных задач;
- персональные рекомендации;
- прогноз прогресса;
- тренировочные сессии;
- преподавательский контроль;
- возможность быстро перевести заинтересованного посетителя в заявку на обучение.

## 9. Быстрый контекст для следующей модели

Если этот документ передается другой модели, начальная формулировка задачи может быть такой:

> У нас есть Django-сайт образовательного проекта "Фрактал". Это MVP платформы подготовки к экзаменам: главная, заявки, аккаунты, личные кабинеты, экзамены, задачи, персональные варианты, рекомендательная система, тренировочные сессии, база курсов и инструменты методиста уже частично реализованы. Нужно составить бизнес-план не для идеи с нуля, а для вывода этого MVP в коммерческий продукт.

Главные вопросы для бизнес-плана:

- кто платит и за что;
- какие тарифы и форматы обучения вводить первыми;
- как использовать уже готовую рекомендательную систему как конкурентное преимущество;
- какие доработки обязательны до первых продаж;
- какие метрики показывать ученикам, родителям и преподавателям;
- как организовать наполнение и контроль качества задач.
