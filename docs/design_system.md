# Минималистичный интерфейс FractalSchool

Актуальное направление на 30 октября 2026: спокойные тёмные и светлые поверхности,
голубая навигация, мятные основные действия, моноширинные данные и спокойная учебная среда.
Ориентир — согласованный прототип страницы прогресса без фоновой сетки.
`home-v2` удалена и больше не является источником дизайна. Старые планы
`site_redesign_*` описывают предыдущие итерации; при расхождении использовать этот документ.

## Общие правила

- Цвета, размеры, шрифты и состояния контролов определяются в `site-foundation.css`.
- Тема хранится как `site-theme=day|night`. `theme-init.js` применяет её до первой
  отрисовки; `site-theme.js` управляет переключением, системной темой и синхронизацией вкладок.
- Светлая тема: нейтральный светло-серый фон, белые панели, тёмно-серый текст,
  спокойные серые границы; глубокий голубой акцент.
  Тёмная: почти чёрный синий фон, тёмно-синие панели, светлый голубой акцент.
- `--color-accent-primary` отвечает за навигацию; `--color-action-primary` — за
  основные кнопки и выбранные задания. Основные действия мятные в тёмной теме
  и глубокие зелёные в светлой. Обычные строки имеют нейтральные границы.
- На тёмной теме допускаются мягкие градиенты в обзорной шапке и прогрессе.
  Светлая тема использует белые поверхности без цветного свечения.
  Сетки и фоновые анимации не используются.
- Фиолетовый — дополнительный смысловой акцент. Ошибки, предупреждения и успех
  используют собственные семантические цвета в обеих темах.
- Интерфейс, заголовки, условия задач и длинные тексты используют обычный шрифт
  (`--font-ui` и `--font-display` основаны на `--font-reading`). Числа и код —
  моноширинный (`--font-data`, `--font-mono`). Полосы прогресса тонкие;
  в светлой теме заполнение одноцветное. В списке типов полоса отступает от краёв.
- Числовые поля используют отдельный затемнённый фон `--color-input-bg`;
  дорожки прогресса — `--color-progress-track`. У нулевого прогресса есть
  декоративная стартовая отметка 3 px, числовое значение остаётся 0%.
  Проценты в списке типов показываются без обводки. Заголовки режимов — без иконок.
- Статус передаётся текстом и оформлением. Фокус с клавиатуры всегда видим.
- Основные интерактивные элементы имеют удобную область нажатия; мобильная версия
  использует одну колонку. Широкие таблицы и код прокручиваются внутри своего блока.

## Организация стилей

- `site-foundation.css`: общая палитра, каркас, кнопки, формы, панели, навигация.
- `courses.css`, `course-module.css`, `system-journal.css`: стили своих разделов,
  подключаются только на соответствующих страницах.
- `solver.css`: только компоновка решателя и его специализированные состояния.
- `homepage.css`, `exam-detail.css`, `training-builder.css`, `lesson-calendar.css`:
  композиция соответствующих разделов с общими переменными.
- `task-statement.css`, `markdown-code-blocks.css`: читаемость учебного контента.
- `partials/theme_toggle.html`: общий переключатель для сайта и решателя.
- `base_learning.html`: добавляет библиотеки формул, кода и стили учебного контента.
  Главная, вход, кабинет и расписание эти библиотеки не загружают.
- `base_solver.html`: наследует общий каркас, убирает обычную шапку и подвал,
  добавляет раскладку решателя. Метаданные и общие подключения не дублируются.
- `partials/task_interaction_js.html`: помощники интерактивных задач, подключаются
  только в тренировке и решателе до их инициализации.
- `application-price.js`, `teacher-skillset.js`, `variant-basket.js`: отдельные
  сценарии заявки, умений преподавателя и корзины. Загружаются там, где нужны.
- `training-builder.js` управляет составом на странице экзамена и типа,
  `training-solver.js` — тренировкой в общем решателе.

## Стандартизация 30 октября 2026

Общая система применяется к гостевым страницам, кабинету ученика, курсам,
расписанию и рабочим инструментам преподавателя. Стандартная Django admin
сохраняет своё оформление. Разделы используют общие компоненты, а не одинаковую
компоновку: календарь, граф курса и решатель сохраняют специализированную раскладку.

| Элемент | Общее правило |
|---|---|
| Заголовок страницы | `--font-size-page-title`: 26–36 px, `.page-title` для отступа |
| Заголовок раздела / карточки | `--font-size-section-title`: 20–24 px / `--font-size-card-title`: 20 px |
| Карточка | `.card` / `.block`, нейтральная рамка, `--radius-md`, `--panel-padding` |
| Основное / второстепенное действие | `.btn.btn-primary` / `.btn.btn-secondary` |
| Текстовое действие | `.btn.btn-link`, без постоянной рамки |
| Поле | `--color-input-bg`, `--color-border-control`, `--radius-sm`; общий фокус 2 px |
| Сетка формы | `.form-grid`, `.form-field`, `.form-field--wide`, `.form-actions` |
| Данные | `--font-data` / `.data-value`; код — `--font-mono` |
| Статус | Семантические `--color-success/danger/warning`, соответствующий `-soft` фон; текст обязателен |
| Прогресс | `--progress-height`: 6 px, `--color-progress-track`, стартовая отметка 3 px |
| Учебный контент | Одна внешняя карточка, широкие таблицы и формулы прокручиваются внутри условия |

Обычные подписи и статусы используют шрифт интерфейса; моноширинный шрифт
сохранён для данных и кода. Декоративные рамки обычных карточек нейтральные;
цветная граница используется для выбранного элемента, фокуса или статуса.
`block--futuristic` оставлен как совместимый класс с обычным оформлением `.block`.
Вложенная форма не создаёт дополнительную карточку; самостоятельная `form.card`
сохраняет белую/тёмную поверхность. Поля с `aria-invalid="true"` отмечаются цветом ошибки.

Локальные CSS подключаются через `{% versioned_static %}` с хешем содержимого.
При изменении компонента браузер получает новую версию его стилей автоматически.
Не добавлять датированные версии CSS и не копировать общие кнопки/поля в стили раздела.
Особенности учебных таблиц, календаря, графа и компактного решателя остаются
в соответствующих файлах компонентов.

Проверки этой итерации перечислены в [отчёте стандартизации](design_standardization.md).

## Страница экзамена: 23 октября

Аналитика свёрнута в единую полосу с прогнозом и прогрессом; пояснения раскрываются.
Готовые варианты и акцентная сборка персонального пробника идут перед типами.
Карточки типов занимают одну строку, темы и теги раскрываются нажатием строки
или доступной с клавиатуры стрелки. Ссылки и поля сохраняют собственное действие.
Покрытие тегов выделено отдельно от заданных минимумов. Просмотр состава,
история, архив и переключение годов расположены ниже основного сценария.
Уведомления сохранения не меняют высоту страницы. Подробности сценария:
[training_variants.md](training_variants.md).

## Проверка изменений

Проверять светлую и тёмную тему на ширинах 375, 768 и 1440 px, сохранение выбора
после переходов, видимость фокуса и отсутствие горизонтального переполнения страницы.
Для учебных страниц проверять формулы, код, таблицы, вложения, динамическую загрузку,
сохранение ответа и результаты. Не менять расчёт прогресса ради визуального прототипа.
Пользовательские страницы и служебные интерфейсы используют одну систему.
Стандартная Django admin сохраняет собственное оформление.

## Проверка первой итерации 19 октября 2026

- Скомпилированы все 50 Django-шаблонов, `manage.py check` и `git diff --check`
  проходят.
- В Chromium открыты 25 страниц и состояний гостя, ученика и преподавателя.
  Проверены обе темы на ширинах 375, 768 и 1440 px; ошибок JavaScript нет.
- После исправления мобильного календаря и конструктора выполнены 24 повторные
  проверки раскладки календаря, конструктора и результатов завершённого варианта:
  горизонтального переполнения страницы нет. Широкие таблицы прокручиваются внутри.
- Пройдены 10 браузерных проверок темы: системная настройка и её изменение,
  клавиатура, сохранение выбора, синхронизация вкладок, доступная подпись,
  reduced-motion, отсутствие ASCII и работа при недоступном localStorage.
- Из 109 существующих тестов учебного контента, тренировок, вариантов, кабинета,
  занятий, прогресса и служебных страниц прошли 108. Существующий тест
  `accounts.tests.DashboardAssignmentsViewTests.test_dashboard_shows_training_sessions`
  ожидает неэкранированные кавычки JSON в HTML. Он падает также с исходным
  `accounts/dashboard.html` из HEAD; шаблон истории не изменялся.
- Удалённый `/home-v2/` возвращает 404. Расчёт прогресса, модели, миграции,
  сохранение ответов и API редизайн не меняет.

Браузерная проверка выполнена на локальном снимке базы. Полнота media зависит от
локальной копии: у некоторых старых заданий отсутствуют исходные изображения.
Это ограничение локальных данных, отдельно от оформления.

## Финальная ревизия

Проверено после очистки: 134 теста Django прошли, все 55 шаблонов компилируются,
на 25 страницах нет ошибок JavaScript и переполнения страницы при ширинах
375, 768 и 1440 px в обеих темах. Дополнительные браузерные проверки темы,
подключений и интерактивных элементов также прошли.

Устаревшие тестовые данные курсов и ожидание неэкранированного HTML исправлены.
Тест цены использует явно заданный срок акции вместо текущего календарного года;
реальная дата акции в настройках осталась прежней.
