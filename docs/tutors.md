# Репетиторы и запись на занятия

## Что реализовано

- `/tutors/`: опубликованные анкеты, фильтры по предмету, цели и классу, пагинация.
- `/tutors/<slug>/`: описание, образование, стаж, направления, стоимость, публичные контакты.
- В Django admin: «Репетиторы → Анкеты репетиторов», направления и рабочие часы внутри анкеты.
- Анкета связана с существующим `accounts.TeacherProfile`. Рабочая роль не публикует человека автоматически.
- Команда школы и независимые преподаватели используют один каталог. Принадлежность и публикация меняются администратором.
- Кнопка «Выбрать репетитора» на главной. Анкеты добавляются администратором, вымышленных преподавателей нет.
- Фотографии отдаются отдельным маршрутом только для опубликованных анкет: общий media-маршрут проекта принудительно скачивает файлы.

## Первый запуск

1. Применить миграции: `python manage.py migrate` с настройками нужного окружения.
2. Создать аккаунт и `TeacherProfile`, если преподаватель ещё не пользуется кабинетом.
3. В admin создать анкету: имя, стабильный уникальный slug, описание, контакты, направления.
4. Выбрать «Опубликована». Без фотографии показываются инициалы.
5. Для начала оставить «Включить запись через календарь» выключенным: посетители будут обращаться по контактам.

Локально миграции применяются с `--settings=fractalschool.local_settings`.
Production в рамках реализации не изменялся. Новых переменных окружения для каталога не требуется.

## Календарь

Преподаватель с анкетой получает вкладку «Запись ко мне» (`/tutors/manage/`).
Доступны часовой пояс IANA, недельные рабочие промежутки, выходные и дополнительные часы,
перерыв, минимальный срок до занятия, горизонт записи (до 90 дней) и срок подтверждения.
Исключения заменяют недельное расписание на конкретную дату; выходной закрывает весь день.
Рабочие промежутки через полночь разделяются по дням. Пересекающиеся окна не дублируют окошки.
Время хранится в UTC, показывается в выбранном посетителем часовом поясе.
Несуществующие при переходе на летнее время интервалы не предлагаются.

Окошки рассчитываются по длительности выбранного направления с вычетом уроков и резервов.
Цена и длительность фиксируются при бронировании; изменение предложения не меняет существующие записи.
Неуказанная цена должна быть согласована и внесена администратором в запись до подтверждения.

## Жизненный цикл записи

- Посетитель выбирает окошко, вводит имя ученика и контактного лица, контакты, подтверждает передачу данных преподавателю.
- Время резервируется до меньшего из срока подтверждения и начала занятия.
- Преподаватель видит запрос и контакты в «Запись ко мне». Подтверждение создаёт карточку гостевого ученика,
  связь учитель–ученик и урок в существующем расписании. Гость автоматически не связывается с аккаунтом или одноимённым учеником.
- Преподаватель может отклонить запрос, посетитель — отменить его по непредсказуемой персональной ссылке.
- Персональная ссылка показывает статус; она не содержит введённых контактов, не кешируется и не индексируется.
  Ссылку нельзя передавать посторонним: она позволяет отменить запись.
- Отмена подтверждённой будущей записи отменяет соответствующий урок через существующий сервис расписания.
- Уведомления первого выпуска — список запросов в кабинете и статус на персональной странице посетителя.
  Отправка в email/Telegram не подключена; для неё нужно отдельно выбрать канал и настроить доставку.

При записи и подтверждении используется блокировка пользователя-преподавателя, общая с сервисами `lessons`.
Резервы проверяются также при создании и переносе обычных уроков, включая генерацию серий.
Стандартный сценарий использует PostgreSQL; защита от гонок проверена конкурентным тестом на PostgreSQL.
Прямые записи в БД в обход сервисов не поддерживают эту гарантию.

Просроченные резервы сразу игнорируются расчётом доступности независимо от фоновых задач.
Для актуализации статусов в admin можно запускать раз в несколько минут:

```
python manage.py expire_tutor_bookings
```

Статусы также актуализируются при открытии кабинета; cron для корректного освобождения окошек не обязателен.
Ограничение отправки — 10 запросов в час на IP через Django cache. Для нескольких процессов нужен общий cache.

## Проверки

`python manage.py test tutors lessons --settings=fractalschool.local_settings --keepdb`

Самостоятельная публикация сторонних анкет, платежи, комиссии, автоматическая запись без подтверждения
и внешняя синхронизация календарей не входят в текущий выпуск.
