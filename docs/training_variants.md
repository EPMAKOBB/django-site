# Тренировочные варианты и пробники

Актуально на 29 октября 2026 года.

Ученический сценарий начинается на `/exams/<slug>/`: на одной странице доступны
прогресс, сборка тренировки, незавершённые работы и история. Пробник по-прежнему
собирается по спецификации экзамена и использует существующий решатель.

## Сборка

`TrainingDraft` — один черновик на пользователя и версию экзамена. Он содержит
конкретные выбранные задачи с типом, признаком ручного выбора и пояснением подбора,
а также желаемые количества и минимумы по тегам. Черновик сохраняется в базе и
доступен в других браузерах после входа в тот же аккаунт.

Изменение количества сразу подбирает конкретные задачи. На странице типа те же
задачи отмечены галочками. Снятие галочки убирает задачу, установка добавляет её
как выбранную вручную. Такие задачи автоматическое уменьшение количества не
удаляет: сначала нужно снять лишние галочки. Явная очистка удаляет весь состав.

Количество тега — минимум внутри количества типа. Пересекающиеся теги не
дублируют задачи. Подбор старается закрыть минимумы, затем заполняет оставшиеся
места; нехватка доступных задач и незакрытые минимумы показаны явно. Это подбор
с предпочтениями, а не обещание выполнить произвольную систему квот.

Рекомендации дополняют текущий состав до заданного общего количества, сохраняя
ручной выбор и настройки тегов. Используется существующее ранжирование; первый
проход распределяет задачи между несколькими типами, второй заполняет остаток.
Недавно решённые задачи исключаются из рекомендаций, но доступны для ручного
выбора и подбора количества по типу. В одной тренировке допускается до 100 задач.

На странице типа подбор передаёт `type_id`: заданное количество относится только
к этому типу, задачи остальных типов в общем черновике сохраняются. Общий предел
100 задач действует на весь состав, даже при подборе на странице отдельного типа.
Тип из другого экзамена отклоняется сервером.

Запросы изменения передают `revision`. При устаревшей версии сервер возвращает
409, интерфейс загружает актуальный состав и предлагает повторить действие.
Запуск атомарно создаёт вариант и попытку, очищает черновик и увеличивает версию:
двойной запрос не создаёт две работы.

Преподавательская корзина назначений сохраняется как отдельный служебный
инструмент. У ученика на страницах экзамена и типов используется только этот
черновик; дополнительной корзины в ученическом сценарии нет.

## Страница экзамена

После названия идёт компактная раскрываемая аналитика: прогноз и общий прогресс,
внутри — сильные стороны, зоны внимания и пояснения. При суммарном количестве
наблюдений меньше пяти, включая совместимый прошлогодний опыт, интерфейс показывает
«Нужно больше решений». Серверная формула прогноза остаётся прежней.

Далее идёт «Режим экзамена» с готовыми вариантами и кнопкой «Собрать персональный
пробник». Значок «?» открывает подсказку: «Решать полноценный пробник с ограничением
времени. Результат проверяется только после завершения всего варианта».

Следом идёт «Тренировка». Её значок «?» открывает подсказку: «Решать выбранные задачи
без ограничения по времени. Ответы можно проверять сразу». Подсказки открываются
нажатием, Enter или пробелом, закрываются Escape, повторным нажатием, щелчком снаружи
или прокруткой страницы. Их положение учитывает границы окна. Скрипт `exam-detail.js`
подключён с хешем содержимого через `versioned_static`.

Текущая работа показана компактной строкой: «Текущая тренировка · Решено X из Y»,
«Продолжить», «В архив». В этой строке нет сгенерированного названия, дат и числа
введённых ответов. Подсказка «Нажмите на строку…» убрана.
Когда текущей работы нет, строка содержит «Соберите тренировку или верните из архива.»
и рядом количество задач с кнопкой «Подобрать». На узком экране элементы переносятся
внутри той же панели; отдельной строки подбора под ней нет.

Ниже расположены типы и подбор рекомендованных. Свёрнутый тип занимает одну
строку: поле количества, общее число доступных задач, ссылка, название, прогресс
и стрелка. Нажатие строки или стрелки раскрывает темы и теги; ссылки и поля
не переключают раскрытие. Стрелка доступна с клавиатуры и имеет `aria-expanded`.
Фактическое покрытие тега «3 из 4 · в составе» выделено отдельно от поля «Не менее»:
покрытие пересекающихся тегов суммировать как количество задач нельзя.

Финальный просмотр и изменение конкретного состава раскрываются после типов.
Ниже находятся работы, история, архив, переключение годов и удаление экзамена из
актуальных. Добавление ещё не выбранного экзамена показывается вверху с пояснением.
История ответов по датам скрыта в комментарии шаблона для возможного возвращения.
Обычные статусы сохранения убраны; сообщения об ошибках не сдвигают содержимое.

Шаблоны: `templates/exams/detail.html`, `_public_blocks.html`, `_training_builder.html`,
`_training_types.html`. Клиент: `training-builder.js`, `training-solver.js`,
`exam-detail.js` и соответствующие CSS. Старые пошаговые `training.html` и
`training-page.css` удалены как неиспользуемые; redirect и прежние API сохранены.

## Страница типа

`/exams/<slug>/<type>/` предназначена для выбора задач этого типа. Вверху одна
ссылка на экзамен, заголовок «Тип 1 · Теория графов» и число доступных для тренировки
задач. У сотрудника отдельно показаны полный размер банка и число черновиков.
Доступные задачи идут первыми; черновики сохраняются в служебном просмотре и
помечаются, но галочки добавления для них нет.

`_type_training_tools.html` заменяет полный блок управления работами компактной
панелью: количество задач типа, подбор по этому типу, раскрываемые темы и теги,
«Только выбранные». Список задач начинается сразу после панели. Заголовки карточек
уменьшены, условие и заголовок имеют общую карточку без вложенной рамки. Широкие
таблицы прокручиваются внутри условия, не растягивая страницу.

Плавающая панель сохраняет общий размер черновика, очистку и запуск. Нажатие
«В тренировке: N» открывает модальное окно состава с задачами всех выбранных типов
и возможностью удаления; Escape и кнопка закрытия возвращают к списку задач.
При уже начатой тренировке показывается короткое уведомление с продолжением и
ссылкой на управление на странице экзамена. Список архива и пробников на странице
типа не загружается. Гостю доступен просмотр опубликованных задач и ссылка входа.

## Решение и история

Новые тренировки используют `VariantTemplate → VariantAssignment → VariantAttempt`
и `VariantTaskAttempt`. `VariantAttempt.mode` различает `exam` и `training`.
В тренировке нет лимита времени и доступны свободная навигация, автосохранение,
проверка отдельных ответов и повторная проверка.
Последняя открытая задача запоминается в браузере. Кнопка отметки отдельной задачи
«Вернуться позже» убрана 28 октября; прежние отметки сохраняются в данных для совместимости.
В тренировке также убрана кнопка «Сохранить»: ответы сохраняются автоматически,
а «Проверить» сначала ожидает сохранения и затем отправляет ответ на проверку.

Решатель тренировки использует компактную шапку: одна ссылка
«← Информатика · ЕГЭ 2027» одновременно обозначает экзамен и возвращает на его страницу,
рядом находятся «Решено X из Y», значок темы и «В архив». Ссылка ожидает сохранения
ответов перед переходом. Логин, дата и время в названии работы, постоянная плашка
«Без ограничения времени» и повторные кнопки итогов из шапки убраны.

До 20 задач номера расположены над условием рядом с единственной кнопкой «Итоги».
Для большего набора список раскрывается кнопкой «Все задания» и ограничен по высоте.
Номер текущей задачи и её тип показаны над условием. Поле ответа и «Проверить» находятся
в одной компактной панели; при длинном условии она остаётся у нижнего края экрана.
Формы больше двух строк или шести ячеек отображаются в обычном потоке страницы.
Результат проверки показывается только возле ответа, автосохранение — тихим статусом,
ошибки — отдельным видимым сообщением. Пустое неизменённое поле не создаёт локальную
неотправленную правку при переключении задач. Оформление пробников сохраняется.

В итогах и навигации применяется одна схема статусов: зелёный — решено, красный —
нужно исправить, жёлтый — частично верно, фиолетовый — ответ не проверен или требует
ручной проверки, нейтральный — без ответа. Цвет дополняет текстовую подпись.
Изменённый после проверки ответ показывается непроверенным до следующей проверки.

У ученика одна текущая тренировка на версию экзамена. У тренировки два состояния:
текущая и архивная. Сборка новой доступна после явного архивирования текущей.
На странице экзамена оставлена одна кнопка «В архив»: она архивирует работу,
открывает состав и переводит к сборщику, но не создаёт пустую работу.
Закрытие сайта и возврат на страницу экзамена сохраняют текущую тренировку.
Даже при всех верных ответах она остаётся текущей до явного архивирования.

«Сделать текущей» возвращает ту же архивную работу с её условиями, ответами,
проверками, отметками и временем; прежняя текущая тренировка атомарно уходит в архив.
Просмотр архивной работы не активирует её. Возврат существующей работы доступен
и после архивирования экзамена; её условия берутся из сохранённых снимков.

Каждая проверка ответа сразу сохраняет попытку и влияет на прогресс. Архивирование
не проверяет оставшиеся ответы и не меняет накопленный прогресс. Возврат и повторная
проверка неизменённого последнего ответа не создают нового наблюдения. Пустые ответы
не создают ошибочных попыток. Для заданий с ручной проверкой автоматический результат
не влияет на готовность. Вторичные экзаменационные баллы для тренировок не выводятся.

Несохранённые ответы дублируются в браузере до отправки. «Продолжить позже» и
«В архив» в решателе ожидают успешного сохранения. При архивации из другой вкладки
изменения блокируются сервером; локальные ответы остаются в браузере. После возврата
или перезагрузки ученик явно выбирает восстановление локальных ответов либо ответы
с сервера. Проверка ожидаемого предыдущего ответа защищает от молчаливой перезаписи.

Тренировочное время учитывается по открытым задачам. Выход, скрытие вкладки и архив
останавливают таймер; heartbeat и ограничение 90 секунд после последнего контакта
не позволяют включить многочасовое отсутствие в статистику задачи. Это время
активной вкладки, а не подтверждённая непрерывная работа ученика.

У тренировок состояние задаёт `archived_at`. `completed_at` сохраняет прежнее
значение для пробников. Миграция 0054 переносит старые завершённые тренировки в архив,
сохраняя прежнюю дату в `legacy_completed_at`; из нескольких текущих оставляет
последнюю запущенную, остальные архивирует и останавливает их таймеры. Ответы,
проверки и исходные условия не переписываются. Пробники миграция не изменяет.

Страница экзамена показывает текущую тренировку, отдельный архив и пробники.
Архив и пробники загружаются страницами по 20; для строк выбираются значения ответов
и последние проверки без полной истории и текстов условий. В архиве показываются
«Решено X из Y» и число введённых ответов. Из просмотра архива можно добавить
ошибки и нерешённые задачи в черновик, если другой текущей тренировки нет.

Переходы используют общую блокировку пользователя, транзакцию и отдельную версию
жизненного цикла `TrainingDraft.lifecycle_revision`. Изменения решателя передают
`X-Training-Revision`: после архивации и возврата старые запросы остаются устаревшими.
`TrainingOperation` хранит квитанции UUID операций, в том числе проверок:
запоздавший повтор не переключает работы обратно и не перезаписывает новый ответ.

Ограничения: 100 уникальных задач в работе, до 200 минимумов тегов, запрос до 64 КиБ.
По умолчанию допускается до 10 новых тренировок за 600 секунд на пользователя;
пороги настраиваются `TRAINING_CREATE_LIMIT`, `TRAINING_CREATE_WINDOW_SECONDS`,
`TRAINING_REQUEST_MAX_BYTES`. Число архивных работ не ограничивается, автоматического
удаления нет.

Старые `TrainingSession` / `TrainingSessionStep` и их API сохранены для совместимости
и истории. В кабинете эти записи показываются в истории прежнего формата;
страница `/exams/<slug>/training/` перенаправляет в новый сборщик. Старые записи и
ответы не преобразуются и не удаляются.

## Основные API

- `GET/POST /api/exams/<id>/training-draft/`: состав; действия `count`, `toggle`,
  `recommend`, `clear`, `start`, `mistakes`.
- `GET /api/exams/<id>/works/?page=1&exam_page=1`: `current_training`, страницы
  `archive` и `exams`, а также `lifecycle_revision`.
- `GET /api/variants/attempts/<id>/state/`: компактный статус для открытого решателя.
- `POST /api/variants/attempts/<id>/archive/`: `archived`, `lifecycle_revision`,
  `operation_id` (UUID); архивирование либо атомарное переключение.
- `POST /api/variants/attempts/<id>/pause/`: остановка тренировочного таймера.
- `POST /api/variants/attempts/<id>/tasks/<task>/check/`: серверная проверка ответа.
- `POST /api/variants/attempts/<id>/tasks/<task>/flag/`: отметка для возвращения.
- `start` дополнительно принимает `lifecycle_revision` и `operation_id` для
  безопасного повтора после потери ответа. Обычный запуск при текущей работе — 409.
- `save` принимает `expected_answer`; несовпадение с серверным ответом — 409.
- `save`, `focus`, `heartbeat` обслуживают общие попытки. `finalize` остаётся для
  пробников; для тренировок нужно явное архивирование.

Доступ ограничен владельцем. При новой выдаче проверяются публикация задач,
принадлежность типу и году, доступность экзамена и предгенерированных данных.
Начатая работа использует уже существующий механизм снимков условий и ответов.

## Развёртывание и проверки

Нужны миграции до `recsys.0054` включительно. 0050–0051 добавляют черновик и поля
попытки, существующие варианты получают режим `exam`. 0054 добавляет версии,
квитанции операций и переносит прежние тренировки в новую модель состояний.
Перед применением 0054 сохраняется резервная копия базы. Для локального просмотра используется
обычный `start-local.cmd`; новые миграции применяются локально при подготовке.

Проверки: `manage.py test apps.recsys accounts --settings=fractalschool.local_settings`.
Тесты нового сценария, гонок PostgreSQL и миграции находятся в
`apps/recsys/tests/test_training_builder.py` и `test_training_lifecycle_migration.py`.
Дополнительно проверяется браузерный путь от выбора количества и галочек до
автосохранения, проверки, переключения архива, восстановления локального ответа
после архивации из другой вкладки и повторной сборки по ошибкам.
