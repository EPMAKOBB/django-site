# Загрузка страницы экзамена

Структура экзамена включается в первоначальный HTML: название, варианты,
типы, описания и обязательные теги доступны без запроса `/public/`.
Этот endpoint сохранён для совместимости.

После получения HTML параллельно загружаются:

- один `/progress/` для карточки экзамена, типов и тегов;
- `/training-draft/` для выбранных задач, доступных количеств и ограничений;
- `/works/` для незавершённых работ и истории.

До получения прогресса выводится `—`. `exam-detail.js` публикует обещание
`window.examProgressReady`, которое использует `training-builder.js`.
На странице отдельного типа, где нет первого скрипта, конструктор сам получает
прогресс. Демонстрация не сохраняет данные.

## Совместимость браузерного кеша

JavaScript и стили сборщика и решателя подключаются через тег `versioned_static`
из `accounts/templatetags/versioned_assets.py`. URL содержит хеш содержимого файла:
после изменения кода браузер получает новый ресурс даже при сохранённой старой
копии. Это обязательно при изменении формата `/works/`: прежний клиент ожидал
массив и выдавал `works.filter is not a function` при получении нового объекта.

Запросы сборщика ограничены 15 секундами. Ошибка, несовместимый ответ и превышение
времени ожидания заменяют первоначальное «Загружаем тренировку» сообщением об ошибке
и кнопкой «Повторить загрузку». Персональные GET-запросы используют `cache: no-store`.
Проверка браузера должна включать уже закешированный прежний JavaScript, ошибку API,
зависший запрос и восстановление списка через повтор загрузки.

## Кеш справочников

`service_utils/exam_catalog.py` хранит словари предметов, экзаменов, типов, тегов,
активных спецификаций и шкал. В кеше нет моделей ORM, пользователей, HTML,
сессионных данных и CSRF-токенов. Варианты проверяются по актуальному состоянию
публикации заданий, а доступные количества вычисляет конструктор тренировки.

Ключ кеша содержит UUID из строки `ExamCatalogRevision(pk=1)`. На тёплом кеше
нужен один запрос версии; разные процессы Django видят одинаковую версию,
даже при `LocMemCache`. TTL содержимого — сутки, после перезапуска процесса
оно собирается заново. При отсутствии записи версии она создаётся автоматически.

Сохранение/удаление справочников и изменение `TaskType.required_tags` меняют
версию в той же транзакции. После её фиксации другие процессы перестают
использовать старые ключи. Откат транзакции откатывает и версию.

`QuerySet.update()`, `bulk_create()`, `bulk_update()` и прямой SQL обходят
сигналы. После таких импортов необходимо вызвать `invalidate_exam_catalog()`
в транзакции импорта либо выполнить:

```powershell
.\.venv\Scripts\python.exe manage.py refresh_exam_catalog --settings=fractalschool.local_settings
```

Миграция `recsys.0053` создаёт таблицу версии. Она должна быть применена
перед запуском новой версии приложения. Работа выполнялась только локально.
