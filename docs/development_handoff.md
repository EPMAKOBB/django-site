# Продолжение разработки на другом устройстве

Контрольная точка: 13 сентября 2026 года, ветка `work/local-development-2026-09-13`.

Это общий снимок незавершённой локальной разработки, а не выпуск на рабочий сервер. Он включает ежегодные версии экзаменов, учёт учеников, расписание занятий, связанные изменения кабинета и главной страницы. В `main` настроен автоматический деплой; не сливайте туда эту ветку только ради переноса между устройствами.

## Что получить из Git

```text
git clone --branch work/local-development-2026-09-13 https://github.com/EPMAKOBB/django-site.git
cd django-site
python -m venv .venv
```

В Windows установить зависимости:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

На исходном компьютере использовались Python 3.11, Django 5.2.9 и PostgreSQL 17.6. Виртуальное окружение на новом устройстве создаётся заново.

## Что переносится отдельно

- Дамп базы, в которой действительно ведутся ученики и расписание; при необходимости — отдельный дамп экспериментальной базы экзаменов.
- Файлы из `media` и нужные загрузки `.local/exam-sandbox/media` с сохранением относительных путей.
- Настройки окружения и секреты через защищённый канал. В Git их не добавлять.

Каталоги `.git/exam-year-pg` и `.git/exam-year-checkpoints` существовали только на исходном устройстве и не переносятся через Git. Для PostgreSQL нужен логический дамп и восстановление; копирование работающего каталога данных не заменяет резервную копию. Сам пуш этой ветки не создаёт дамп базы.

На новом устройстве сначала установить PostgreSQL, создать локальную роль/базу и восстановить дамп. Затем настроить Django на эту локальную базу и применить миграции. Не использовать адрес рабочего сервера для экспериментов.

Настройки `fractalschool.exam_sandbox_settings` рассчитаны на локальные `127.0.0.1:55438`, роль `examdev` и базу `exam_year_sandbox`. Они изолируют базу и загрузки от рабочей `.env`. На другом устройстве нужно либо подготовить эти параметры, либо осознанно адаптировать локальные настройки. Пути к PostgreSQL в инструкции ниже относятся к исходному Windows-компьютеру.

## Известный результат проверок

Перед сохранением контрольной точки Django check проходит, новых изменений моделей без миграций не обнаружено. Локальный PostgreSQL в этот момент остановлен: проверка согласованности истории миграций с базой повторно не выполнялась.

Ранее на изолированном PostgreSQL проходили 126 тестов recsys. В расширенном наборе из 233 тестов оставались 4 failures и 10 errors, воспроизведённые и на исходной рабочей копии: дата акции, отсутствие Node для части JS-тестов, Task без slug в тестах courses и ожидание неэкранированного JSON в тесте кабинета accounts. Эти сведения не означают завершённую приёмку всех параллельных направлений разработки.

После восстановления окружения проверить сайт, админку, учеников, календарь, создание экзаменационного сезона и профильные тесты. Браузерная приёмка сезонов и архитектурное разделение recsys ещё не завершены. История чатов через Git не переносится; этот файл и профильные инструкции служат исходным контекстом для следующей сессии.
