# Как запустить тестовый сайт и попробовать новый сезон

Инструкция для вашего компьютера: Windows, PowerShell, проект `D:\FS\django-site`. Подготовлена 12 сентября 2026 года.

Будет отдельный сайт по адресу **http://127.0.0.1:8001/**, отдельная база `exam_year_sandbox` и отдельные загружаемые файлы. Рабочую `.env` менять не нужно. Во всех командах Django ниже явно указаны новые настройки `fractalschool.exam_sandbox_settings`: они используют только локальный PostgreSQL и игнорируют адрес рабочей базы из `.env`.

На этом компьютере уже есть PostgreSQL на порту 55438 и восстановленная база `exam_year_restored` с задачами и историей. Из неё вы создадите ещё одну копию для своих экспериментов. `exam_year_restored` останется исходной точкой. Базу `exam_year_dev` и настройки `postgres_test_settings` для этого сценария использовать не нужно: они предназначались для автоматических проверок.

## 1. Открыть PowerShell в проекте

Все последующие команды выполняйте в одном окне PowerShell:

```powershell
Set-Location 'D:\FS\django-site'
$pgBin = 'C:\Program Files\postgresql-17.6-1-windows-x64-binaries\pgsql\bin'
$pgData = 'D:\FS\django-site\.git\exam-year-pg\data'
```

Проверить Python из имеющегося виртуального окружения:

```powershell
.\.venv\Scripts\python.exe -c "import django, psycopg2; print(django.get_version())"
```

Ожидается `5.2.9`. Активация окружения и изменение политики выполнения PowerShell не нужны: команды вызывают Python напрямую. Если зависимостей не хватает:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

## 2. Проверить локальный PostgreSQL

```powershell
& "$pgBin\pg_ctl.exe" -D $pgData status
```

Если указано `server is running`, переходите к следующему шагу. Если сервер остановлен, запустите именно подготовленный кластер:

```powershell
$pgStartArgs = @('-D', $pgData, '-l', 'D:\FS\django-site\.git\exam-year-pg\server.log', '-o', '"-p 55438 -h 127.0.0.1"', 'start', '-w')
$pgStarter = Start-Process -FilePath "$pgBin\pg_ctl.exe" -ArgumentList $pgStartArgs -WindowStyle Hidden -PassThru
$null = $pgStarter.WaitForExit(15000)
& "$pgBin\pg_ctl.exe" -D $pgData status
```

Проверить доступные базы:

```powershell
& "$pgBin\psql.exe" -h 127.0.0.1 -p 55438 -U examdev -d postgres -c "SELECT datname FROM pg_database WHERE datname LIKE 'exam_year_%' ORDER BY datname;"
```

В списке должна быть `exam_year_restored`. Если её нет или нет каталога `$pgData`, остановитесь: эта инструкция опирается на уже подготовленное локальное окружение, а не на произвольную установку PostgreSQL.

## 3. Один раз создать свою копию базы

```powershell
& "$pgBin\createdb.exe" -h 127.0.0.1 -p 55438 -U examdev --template=exam_year_restored exam_year_sandbox
```

Успешная команда обычно ничего не выводит. Если база `exam_year_sandbox` уже существует, пропустите этот шаг: повторно создавать или удалять её для обычного запуска не нужно. Если PostgreSQL сообщает, что исходная база используется другими сеансами, закройте локальные процессы и окна SQL-клиента, подключённые к `exam_year_restored`, и повторите создание копии.

Теперь проверьте, куда подключится Django. Команда не выводит пароль:

```powershell
.\.venv\Scripts\python.exe manage.py shell --settings=fractalschool.exam_sandbox_settings -c "from django.conf import settings; d=settings.DATABASES['default']; print(d['HOST'], d['PORT'], d['NAME']); print(settings.MEDIA_ROOT)"
```

Ожидается:

```text
127.0.0.1 55438 exam_year_sandbox
D:\FS\django-site\.local\exam-sandbox\media
```

## 4. Подготовить схему и проверить перенос

```powershell
.\.venv\Scripts\python.exe manage.py migrate --settings=fractalschool.exam_sandbox_settings
.\.venv\Scripts\python.exe manage.py check --settings=fractalschool.exam_sandbox_settings
New-Item -ItemType Directory -Force '.local\exam-sandbox\reports' | Out-Null
.\.venv\Scripts\python.exe manage.py backfill_exam_context --apply --report=.local/exam-sandbox/reports/backfill.json --settings=fractalschool.exam_sandbox_settings
.\.venv\Scripts\python.exe manage.py audit_exam_context --report=.local/exam-sandbox/reports/audit.json --settings=fractalschool.exam_sandbox_settings
```

После каждой команды убедитесь, что нет ошибки, прежде чем продолжать. В исходной восстановленной базе миграции и перенос уже применены, поэтому здесь нормально увидеть `No migrations to apply` и отсутствие новых обработанных ответов. Повторный перенос не создаёт копии решений.

На исходной копии были 1059 задач, 2664 Attempt и 1048 годовых назначений. У 11 задач отсутствует годовой тип, а контекст старых ответов помечен `inferred`: это известные ограничения прежних данных, а не ошибка запуска. `seed_ege` выполнять не нужно — в копии уже есть банк.

## 5. Подготовить файлы и вход

База не содержит сами изображения и вложения. Если они есть в локальной папке `media`, один раз скопируйте их в отдельную папку тестового сайта:

```powershell
New-Item -ItemType Directory -Force '.local\exam-sandbox\media' | Out-Null
if (Test-Path -LiteralPath '.\media') {
    Get-ChildItem -LiteralPath '.\media' -Force | Copy-Item -Destination '.local\exam-sandbox\media' -Recurse
}
```

Это копирование, а не перенос исходных файлов. Если локальной `media` нет, настройку сезонов можно проверять без неё; задания с отсутствующими файлами будут отображаться неполно. Для проверки таких заданий нужна копия медиа с сохранением относительных путей. Старые абсолютные ссылки, сохранённые внутри условий и снимков, могут по-прежнему вести на прежний адрес — настройки не переписывают историю.

Создайте отдельного локального администратора, например с именем `season_test_admin`:

```powershell
.\.venv\Scripts\python.exe manage.py createsuperuser --settings=fractalschool.exam_sandbox_settings
```

Команда спросит логин, почту и пароль. Если администратор уже создан, пропустите её. При необходимости изменить его пароль:

```powershell
.\.venv\Scripts\python.exe manage.py changepassword season_test_admin --settings=fractalschool.exam_sandbox_settings
```

Пароли существующих пользователей также скопированы, но создавать отдельную тестовую учётную запись удобнее. Новые загрузки сохраняются только в `.local\exam-sandbox\media`. Django-письма выводятся в консоль вместо отправки через почтовый сервер.

## 6. Запустить сайт

```powershell
.\.venv\Scripts\python.exe manage.py runserver 127.0.0.1:8001 --settings=fractalschool.exam_sandbox_settings
```

Оставьте это окно открытым. Перейдите в браузере:

- Сайт: http://127.0.0.1:8001/
- Админка: http://127.0.0.1:8001/admin/
- Экзамены: http://127.0.0.1:8001/admin/recsys/examversion/

Войдите созданным администратором. Для проверки ученического сценария используйте отдельную учётную запись и другое окно браузера. Сервер слушает только ваш компьютер. Стили обслуживаются режимом разработки; `collectstatic` для этого запуска не требуется.

## 7. Попробовать новый сезон одного предмета

1. В списке экзаменов откройте исходный экзамен нужного предмета, например информатику ЕГЭ 2026.
2. Нажмите «Создать следующий год», укажите 2027 и ЕГЭ. Оставьте флажок новой редакции текущего года выключенным: сейчас создаётся следующий год.
3. Откройте созданный черновик. Проверьте типы, обязательные темы, структуру вариантов и шкалу.
4. В соответствии типов настройте пробную перенумерацию. Для простого сохранения содержания можно изменить название/номер нового типа с 13 на 10; старый тип 2026 не редактируйте. Не оставляйте случайно два новых типа с одинаковым предполагаемым официальным номером.
5. Подтвердите проверенные соответствия. Для разделения, объединения или частичного переноса задайте конкретные ID задач в `task_ids`, например `[501, 502]` — только если такие задачи действительно входят в нужный исходный пул. Не копируйте карточки задач ради нового года.
6. Нажмите «Проверка и публикация». Исправьте замечания отчёта. В поле документа для локального эксперимента можно написать «Локальная тестовая конфигурация, не официальная спецификация». Подтверждения и публикация здесь относятся только к вашей тестовой базе.
7. Опубликуйте пробный сезон. До публикации черновик недоступен для обычной новой тренировки. Проверьте каталог, запуск тренировки и сборку варианта; затем откройте старую историю и убедитесь, что там сохранился старый тип.
8. Повторите отдельно для другого предмета. Массовое создание сезонов сразу по всем предметам не добавлялось.

Для первого знакомства можно сначала опубликовать полностью проверенную копию с прежней структурой, а сложные разделения типов проверить в отдельном черновике. Публикация блокирует обычное редактирование требований: дальнейшие содержательные изменения проверяются через новую редакцию. Заполненная копия содержит реальные исторические записи, поэтому это уже полезная проверка сохранности старых работ.

Подробные правила соответствий, статистики и ограничения восстановления описаны в [инструкции ежегодного перехода](exam_year_transition_release.md).

## 8. Остановка и следующий запуск

Остановить Django: нажать **Ctrl+C** в окне с сервером. Данные и созданный сезон сохранятся в `exam_year_sandbox`.

При следующем запуске достаточно проверить PostgreSQL (шаг 2) и выполнить:

```powershell
Set-Location 'D:\FS\django-site'
.\.venv\Scripts\python.exe manage.py runserver 127.0.0.1:8001 --settings=fractalschool.exam_sandbox_settings
```

Повторять копирование базы, файлов и создание администратора не нужно. После обновления кода применяйте миграции с теми же sandbox-настройками перед запуском.

Если локальный PostgreSQL больше никому не нужен, после остановки Django можно остановить именно подготовленный кластер:

```powershell
& 'C:\Program Files\postgresql-17.6-1-windows-x64-binaries\pgsql\bin\pg_ctl.exe' -D 'D:\FS\django-site\.git\exam-year-pg\data' stop -m fast
```

Это остановит доступ и к другим проверочным базам этого кластера. Их данные сохранятся.

## Если что-то не запустилось

| Сообщение / симптом | Что проверить |
| --- | --- |
| Connection refused, порт 55438 | Запущен ли PostgreSQL из шага 2. |
| Database exam_year_sandbox does not exist | Создана ли копия на шаге 3. |
| Relation / column does not exist | Выполнены ли миграции с `exam_sandbox_settings`. |
| Порт 8001 занят | Закройте прежний локальный runserver, затем повторите запуск. |
| Не работает вход | Используйте локального администратора; при необходимости выполните `changepassword` с sandbox-настройками. |
| Нет картинок / вложений | Проверьте копию медиа из шага 5; одного дампа базы недостаточно. |
| Нет действия создания года | Открыта ли карточка `ExamVersion` в админке под суперпользователем. |
| Новый сезон не виден в тренировках | Прошёл ли он проверку и публикацию; черновики не выдаются ученику. |

Эти команды предназначены для локального эксперимента. Перенос на рабочий сайт выполняется отдельно по [инструкции выпуска](exam_year_transition_release.md), после проверки вашего сценария.
