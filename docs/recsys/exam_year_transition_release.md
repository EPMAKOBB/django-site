# Ежегодные версии экзамена: реализация и выпуск

Дата проверки: 12 сентября 2026 года. Основной механизм реализован в рабочем каталоге. Рабочая база и сервер не обновлялись; настоящий экзамен 2027 не публиковался. [План с отметками](exam_year_transition_plan.md) и [исследование](exam_year_transition_research.md).

Для самостоятельной проверки в браузере используйте [пошаговую инструкцию запуска локального тестового сайта](exam_year_sandbox.md). Она создаёт отдельную копию базы для экспериментов и использует настройки `exam_sandbox_settings`, а не настройки автоматических тестов.

## Что работает

Одна запись `Task` имеет несколько назначений `TaskPlacement`. Например, задача #501 может входить в тип 13/2026 и тип 10/2027. Ученические ответы остаются отдельными фактами со своим годом, типом и назначением. Переход не копирует задачи, ответы, файлы или учеников.

При выдаче тренировки, варианта и рекомендации сохраняются содержание, данные генератора, правила оценивания и контекст. У работы дополнительно сохраняются состав, порядок, лимит времени и шкала. Новая редакция задачи не подменяет уже выданное условие. Повтор запроса с тем же ключом не создаёт второе начисление; параллельные ответы обновляют агрегаты под блокировками. Прямой совместимый API без предварительной выдачи фиксирует доступный контекст при записи (`recorded`), но не заявляет, что сохранил ранее показанную генерацию.

Каталог, рекомендации, сборка вариантов и редактор учитывают назначения. В редакторе можно добавить задачу в тип другого года, сохранив исходную классификацию. При неоднозначном прямом запросе API требуется назначение. Вариант собирается из различных задач даже при пересечении пулов типов.

Публикация нового года сохраняет выбор существующего ученика и открытые работы. Новые пользователи получают контекст рекомендуемой версии, существующие — выбранной подготовки. Ученик может явно добавить другой экзамен в подготовку. Архив прекращает новые запуски этого экзамена, сохраняет выданные работы и не архивирует общие задачи.

## Как методист переходит на следующий год

1. Открыть исходный экзамен в административном интерфейсе и выбрать «Создать следующий год». Указать год и вид экзамена. Повторное создание того же черновика не создаёт дублей.
2. В черновике проверить названия и порядок новых типов, обязательные учебные теги, критерии, структуру вариантов и шкалу. Тип нового года имеет собственный ID даже при прежнем номере.
3. Проверить соответствия старых и новых типов. Для неизменных требований доступно массовое подтверждение. Для `partial`, `split` и `merge` указать конкретные ID подходящих задач в JSON-списке `task_ids`. Новые и удалённые типы оформить как `added` и `removed`. Прежний общий процент не распределяется по номерам автоматически.
4. Открыть проверку года. Исправить неподтверждённые соответствия, непокрытые требования, ошибки оценивания и нехватку различных задач для полного варианта.
5. Указать документ и редакцию требований, подтвердить методическую проверку. Перенесённая шкала первоначально выключена: включать её следует после проверки. Допускается публикация с отключённой шкалой и явным подтверждением этого решения.
6. Опубликовать проверенную конфигурацию; при необходимости рекомендовать её новым пользователям. Публикация выполняется транзакционно. Архивировать старый год можно отдельно, когда прекращается новая выдача этого формата.

Опубликованные требования, структуры и шкалы защищены от обычного редактирования. Для содержательного исправления используется действие создания новой редакции текущего года. Прямые SQL-запросы и `QuerySet.update()` обходят часть модельных проверок и не являются способом ежегодного перехода.

Существующие команды импорта сохраняют совместимость через исходные `Task.type` и `Task.exam_version`. Для дополнительных лет используются назначения, а не массовая перезапись этих полей. Полное удаление совместимости — отдельный P9 после эксплуатации новой схемы. Для одновременной выдачи разных редакций содержания одной задачи потребуется отдельная модель редакций; текущий выпуск сохраняет уже выданные снимки.

## Значение статистики

| Показатель | Правило |
| --- | --- |
| Ответы в формате года | Собственные `Attempt.exam_version` и `Attempt.task_type`; период ограничивает фактическую историю, включая баллы и время. |
| Правильные ответы | `is_valid_attempt=True` и `is_correct=True`; частичный балл сам по себе не означает полный правильный ответ. |
| Опыт прежних лет | Совместимые правильные события по постоянным ID задач; новые события не создаются. Эта величина не прибавляется к числу фактических ответов выбранного года. |
| Покрытие темы | Число различных правильно решённых подходящих задач / число задач темы в текущем опубликованном банке. Повторы одной задачи не увеличивают покрытие. |
| Видимый прогресс | Сохранена прежняя формула: при банке темы до 5 задач — доля решённых; при большем банке — до 5 различных правильных задач. По типу берётся среднее всех обязательных тем, включая непроверенные с нулём. Это не вероятность балла на экзамене. |
| Учебные оценки знаний | Существующая модель тегов/навыков учитывает события и забывание; используется в рекомендациях. Давность и сложность не добавлены к формуле видимого покрытия. Отдельная калиброванная оценка уверенности не вводилась. |
| Состояние на дату | Неизменяемый `ExamProgressSnapshot`; дальнейшие ответы и изменения банка его не пересчитывают. |

Для переноса полного свидетельства проверяются сохранённые критерии, схема ответа, максимум и, для статического снимка, условие/ответ. Новые обязательные темы остаются непокрытыми. Для разделений и объединений применяется конкретный набор назначений, а не копирование старого TypeMastery. Неполные старые свидетельства сохраняют отметку происхождения. Недостающие темы видны в прогрессе и доступны обычной тренировке; отдельный автоматический диагностический вариант ещё не реализован.

`recompute_mastery` по умолчанию восстанавливает учебные агрегаты из событий теми же правилами, что применяются к новым ответам. `--as-of` задаёт фиксированный момент забывания и не должен быть раньше последнего ответа. Повтор на одну дату проверен. `--legacy-ratio` явно включает прежнюю формулу correct/total и не предназначен для штатного ежегодного перехода. Пересчёт не копирует ответы и не меняет архивные снимки.

Ограничения восстановленных данных:

- У всех 2664 старых `Attempt` происхождение контекста — `inferred`. Точный исходный тип ранее не записывался; отсутствие `unknown` не означает доказанную историческую точность.
- 11 задач не имеют годового типа: 16, 17, 19, 20, 21, 22, 24, 25, 165, 166, 194. Их назначение требует разбора; произвольная классификация не выполнялась.
- У всех 292 старых работ исходная шкала неизвестна. Текущая шкала не выдается за историческую. Другие восстановленные поля также содержат отметки происхождения.
- У работы #40 нет сохранённых выданных задач, хотя нынешний шаблон содержит 31. История показывает сохранённый пустой состав. Причину отсутствия выдачи из этих данных установить нельзя.
- Снимки `before_backfill` сохраняют прежние значения TypeMastery, а не точную реконструкцию старого экрана прогресса.

Повторные запуски переноса не добавили назначений или ответов и не повторяли начисление знаний. Пробное создание черновика из восстановленного экзамена выполнено с откатом транзакции: 27 типов, 30 замечаний проверки; публикация без проверки не допускается.

## Проверки и оставшиеся ограничения выпуска

- 126 тестов `recsys` проходят, включая 40 новых: перенумерация, частичное соответствие, разделение/объединение, новые темы/шкала, снимки, повторные и параллельные ответы, API и административные действия.
- `manage.py check` проходит; `makemigrations --check --dry-run` не находит изменений.
- Расширенный набор: 233 теста, 4 failures и 10 errors. Те же проблемы воспроизведены на сохранённой исходной рабочей копии: дата акции в `applications`, отсутствие Node для JS-тестов, создание Task без slug в `courses`, ожидание неэкранированного JSON в тесте кабинета `accounts`. Эти посторонние изменения не исправлялись в рамках перехода года.
- Синтаксис `static/js/exam-detail.js` проверен JavaScript-движком. Полная ручная проверка браузером не проводилась.
- На копии базы: каталог — 1 запрос / 11 мс; прогресс 27 типов — 10 запросов / 107 мс; 5 рекомендаций выбранного экзамена — 8 запросов / 95 мс вместо 614 / 530 мс до оптимизации. Это локальные замеры, не нагрузочная гарантия. Создание и проверка черновика — 7026 запросов / 3,13 с; отдельный замер календарной истории и оптимизация административного копирования остаются открытыми.

Артефакты локальной проверки: `.git/exam-year-pg/` (аудиты, журналы тестов и замеры). Исходная рабочая копия сохранена в `.git/exam-year-checkpoints/20260912-045507/source.zip`; исходный Git HEAD — `de1c99b`. Архив исходников не заменяет резервную копию базы и файлов.

## Порядок первого выпуска

Выпуск выполнять отдельно после устранения/разбора исходных ошибок общего набора, проверки экранов в браузере и аудита свежей рабочей копии. Не применять тестовые настройки к рабочему серверу.

1. Сделать резервную копию рабочей базы и медиа, проверить восстановление в изоляции. Зафиксировать количества событий и примеры старых работ. Сохранить исходные показатели до любых пересчётов.
2. На время первого обновления остановить запись ответов и фоновые задачи, дождаться завершения запросов. Первый выпуск меняет писателей и читателей совместно; отдельного переключателя читателей в нём нет. Не запускать старые процессы после установки нового кода.
3. Применить добавочные миграции проверенного выпуска с рабочими настройками. Сохранить отчёты следующими командами, используя явные настройки нужного окружения:

   ```text
   python manage.py migrate --settings=fractalschool.settings
   python manage.py audit_exam_context --report=audit-before.json --settings=fractalschool.settings
   python manage.py backfill_exam_context --report=backfill-preview.json --settings=fractalschool.settings
   python manage.py backfill_exam_context --apply --batch-size=500 --report=backfill-applied.json --settings=fractalschool.settings
   python manage.py audit_exam_context --report=audit-after.json --settings=fractalschool.settings
   python manage.py backfill_exam_context --apply --report=backfill-repeat.json --settings=fractalschool.settings
   ```

4. Сопоставить отчёты с резервной копией: количества ответов и сохранённые оценки неизменны, дубли отсутствуют, конфликты разобраны, неизвестные поля явно помечены. Команда фиксирует верхнюю границу ID ответов на запуск; повторный проход обрабатывает оставшиеся события. На первом выпуске пауза записи устраняет гонку с устаревшим писателем. Не запускать перенос одновременно из нескольких процессов.
5. Проверить открытый старый вариант, тренировку, историю, приём нового ответа и повтор того же запроса. Возобновить приложение и фоновые задачи только на новом коде. Повторить аудит после возобновления записи.
6. Подготовить годовую конфигурацию через административный мастер. Публикация года — отдельное методическое действие после проверки требований; установка кода сама по себе её не выполняет.

Если нужно прекратить новую выдачу конкретного года, использовать архивирование через мастер: уже выданные ответы продолжают приниматься, история остаётся доступной. Архивирование создаёт снимки прогресса и не является временным переключателем с кнопкой возврата; повторное открытие требует отдельного решения. При общей неисправности остановить выдачу на уровне приложения, сохранив базу с принятыми ответами для исправления.

После появления новых контекстов не откатывать код на старую версию, которая их не понимает. Исправлять текущий выпуск с сохранением данных. Восстановление старой резервной копии возможно только с отдельно спланированным переносом ответов, принятых после неё; автоматического слияния здесь нет. Удаление старых полей и окончательный перевод импортов выполняются отдельным P9 после подтверждения работы на сервере.

Для повторения профильных тестов на локальном изолированном PostgreSQL:

```text
python manage.py test apps.recsys --settings=fractalschool.postgres_test_settings
python manage.py check --settings=fractalschool.postgres_test_settings
python manage.py makemigrations --check --dry-run --settings=fractalschool.postgres_test_settings
```

Эти тестовые настройки игнорируют рабочий `DATABASE_URL`, используют локальный порт 55438 и включают полный граф миграций. Сервер PostgreSQL должен быть заранее запущен; Django создаёт и удаляет отдельную тестовую базу.
