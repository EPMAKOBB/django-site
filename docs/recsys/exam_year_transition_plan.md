**План внедрения ежегодных версий экзамена**

Дата: 12 сентября 2026 года. Статус: основной механизм первого выпуска реализован и проверен на изолированном PostgreSQL. Рабочий сервер не обновлялся. Незавершённые и частично выполненные пункты оставлены открытыми; подробности — в [отчёте и инструкции выпуска](exam_year_transition_release.md).

Основание: [исследование и архитектурное решение](exam_year_transition_research.md). План предназначен для последовательного выполнения: у каждого этапа есть зависимость, перечень действий и проверяемый результат. При выполнении отмечаем завершённые пункты и сохраняем результаты проверок в журнале в конце файла.

**Цель и границы первого выпуска**

Одна задача используется в экзаменах разных лет под разными типами. Старая работа, её классификация и оценка сохраняются. Подготовка к новому экзамену учитывает совместимый прежний опыт. Методист создаёт следующий год через административный интерфейс без ежегодного копирования банка и написания новой миграции.

Первый выпуск включает общий банк, назначения задач, фиксацию контекста решений, архив показателей, перенос совместимых свидетельств знаний, мастер перехода года и изменения пользовательских экранов. Удаление старых полей выполняется отдельным завершающим этапом после подтверждения работы новой схемы.

Условный пример для всех проверок: задача #501 относилась к типу 13/2026 и также включается в тип 10/2027. Это тестовый сценарий, не утверждение об официальной нумерации ФИПИ.

**Зафиксированные решения**

| Вопрос | Решение |
| --- | --- |
| Идентичность задания | Существующий `Task.id` сохраняется при использовании в новом году. |
| Экзаменационный тип | `TaskType` относится к конкретной версии экзамена; каждый год создаются новые записи типов. |
| Применимость задания | Новая модель `TaskPlacement` связывает `Task` с годовым `TaskType`. |
| Контекст ответа | Каждая `Attempt` хранит собственные год и тип, выбранное назначение и зафиксированное содержание/правила выдачи. |
| История результатов | Считается по контексту события, а не по текущей карточке задачи. |
| Готовность к новому году | Отдельная проекция совместимых свидетельств на требования нового экзамена; реальные ответы не копируются. |
| Показатели на дату | Сохраняются в неизменяемом `ExamProgressSnapshot`. |
| Переход типов | `TaskTypeTransition` хранит проверенные соответствия, включая частичные, разделения и объединения. |
| Целевой год ученика | Смена версии по умолчанию не переписывает выбор ученика, назначения учителя и начатые работы. |
| Неполные старые данные | Сохраняются с происхождением и признаком неопределённости; отсутствующая история не выдумывается. |

`TaskRevision` не требуется для простого повторного использования неизменного задания. Если первый выпуск должен поддержать одновременную выдачу разных редакций одной задачи, редакции добавляются до включения этого сценария. До этого содержательные изменения уже используемого задания ограничены: старый материал должен оставаться воспроизводимым. Новая редакция содержания и новый экзаменационный год — разные события.

**Обязательные свойства результата**

- Старый ответ никогда не становится ответом другого типа или другого экзаменационного года из-за изменения банка.
- Добавление 2027 года не создаёт копий `Task`, ответов и доказательств знаний.
- У одной фактической попытки один выбранный контекст. Несколько применимостей задачи не умножают попытку.
- Прежние баллы, максимум, шкала, порядок и показанное условие воспроизводятся из зафиксированных данных.
- Опубликованные использованные требования не меняются задним числом; содержательная правка требует новой редакции конфигурации.
- Архивирование прекращает нужные будущие запуски, но сохраняет доступ владельца и уполномоченного преподавателя к выполненным работам.
- Повторный запуск переноса и пересчёта не изменяет число фактических ответов и не начисляет знания повторно.
- Снимок прогресса на дату не меняется после расширения банка, новых ответов и обновления алгоритма.

| --- | --- | --- |
| P0 | Контрольная точка, исходные проверки и аудит данных | — |
| P1 | Дополнительные модели и поля без удаления старых | P0 |
| P2 | Все новые ответы фиксируют собственный контекст | P1 |
| P3 | Старые данные перенесены с отчётом о полноте | P2 |

| P7 | Пользовательские экраны и архив работают с двумя годами | P5, P6 |
