# Развёрнутые решения: фото и самооценка

Общий механизм для заданий ЕГЭ и ОГЭ со схемой `manual_scaled`. Номера заданий,
предмет и максимальный балл не зашиты в интерфейс. Бинарная проверка и старые
правила частичного оценивания не меняются.

## Материалы автора

В форме создания/редактирования задачи и Django admin доступны три отдельных поля:

- `correct_answer`: итоговый ответ в существующем формате;
- `reference_solution`: образец решения, Markdown и формулы;
- `assessment_criteria`: критерии получения каждого балла, Markdown и таблицы.

Эталон не используется для строкового сравнения развёрнутого решения. Отсутствие
критериев не мешает сохранить фото, но не позволяет выставить самооценку.
Новые материалы попадают в снимок при выдаче работы. Для старой выдачи, в которой
эти поля отсутствовали, они однократно фиксируются при первом открытии страницы
решения. Последующие изменения банка не подменяют сохранённые материалы.

## Путь ученика

В текущем решателе пробника и тренировки у такого задания есть ссылка
«Фото решения и самооценка». Она открывает страницу конкретного задания работы.
Ученик может снять фото с телефона, выбрать изображения из памяти или загрузить
с компьютера. Поддерживаются JPEG, PNG, WebP, до 12 страниц по 10 МБ и до 32 Мп
на исходное фото. HEIC нужно предварительно сохранить как JPEG.

Изображения проверяются Pillow, ориентируются по EXIF и сохраняются в JPEG
без исходных метаданных, с длинной стороной до 2600 px. До отправки можно
поворачивать, переставлять и удалять страницы. Текст решения/комментарий
необязателен; многострочное текстовое поле также остаётся доступно в общем
компоненте ответа для будущих предметов.

После «Отправить решение» содержимое фиксируется. Обычные API сохранения,
очистки и повторной отправки ответа не позволяют заменить его. Для новой
редакции решения нужно начать новую работу; редактирование уже отправленной
фотоработы пока не реализовано.

В тренировке образец можно открыть после отправки решения; в пробнике — после
завершения всей работы. Открытие материалов фиксируется в `revealed_at`.
Самооценка — целое число от нуля до максимума выданного задания. История оценок,
автор, дата и комментарий сохраняются отдельными записями `SolutionAssessment`.

Самооценки учитываются в первичном результате работы с явной подписью, но пока
не включаются в автоматические показатели освоения и сложности задач.
Ответы, ожидающие оценки, также не считаются неудачами. При наличии таких
ответов результат предварительный, перевод в тестовый балл не показывается.

## Телефон и приватность

На странице задания можно открыть QR-код/ссылку для телефона. QR создаётся
локально библиотекой qrcode, без внешнего сервиса. Ссылка действует 15 минут,
не требует входа на телефоне и позволяет только загрузку/просмотр фото этого
решения. Она не позволяет отправлять работу, видеть критерии или выставлять
баллы. Ссылку можно отозвать; отправка решения также немедленно отключает её.
POST-запросы защищены CSRF, в том числе на странице временной ссылки.

Страницы решения не включают Метрику и общий виджет сайта. Политика referrer
`same-origin` не отправляет ссылку внешним сайтам, сохраняя работоспособность
проверки CSRF при HTTPS. Ответы и фотографии имеют `Cache-Control: private,
no-store`. На публичном `/media/` доступ к `_private_solutions` запрещён.

С компьютера, открытого по `127.0.0.1`/`localhost`, QR для другого устройства
не показывается: телефон не может обратиться к loopback компьютера. На рабочем
домене используется обычный HTTPS URL. Для проверки в локальной сети требуется
отдельная осознанная настройка адреса, allowed hosts и CSRF; основной локальный
запуск по-прежнему слушает только loopback.

## Хранение и обновление

Миграция `recsys.0055` добавляет два поля задачи и таблицы `WrittenSolution`,
`SolutionPhoto`, `SolutionAssessment`. Существующие задачи, оценки и схемы
не переписываются. Зависимость Python: `qrcode`.

Фото хранятся файловым хранилищем в `MEDIA_ROOT/_private_solutions`, а не в
публичном S3-хранилище. Для production этот каталог должен находиться на
постоянном volume и входить в резервное копирование вместе с БД. Существующий
Railway volume `/app/media` подходит, если `MEDIA_ROOT` указывает туда.
При отдельной раздаче media через reverse proxy/CDN этот приватный подкаталог
также следует исключить из публичной раздачи. Удаление файла через интерфейс
удаляет и его запись. При удалении записи фото, в том числе каскадно,
удаление файла выполняется после успешного завершения транзакции.

Перед обновлением сервера сделать резервную копию БД и volume, установить
requirements, применить миграции и выполнить collectstatic штатным способом.
Изменения этой задачи подготовлены локально, production не обновлялся.

## Импорт

Команда `import_free_response_tasks --path FILE --exam-version-id ID
--source-variant-id ID` сначала проверяет пакет без записи. `--apply` записывает
все задачи как черновики в одной транзакции и создаёт назначения с
`manual_scaled`. Повтор существующих slug отклоняется.

Каждая запись JSON содержит `type_number`, `slug`, `title`, `description`,
`correct_answer` (строка), а также необязательные `reference_solution` и
`assessment_criteria`. Типу нужна активная схема `1×1`, `ui_hint: textarea`,
`input_type: text`, `manual_check: true`. Это настройка формата текстового
эталона, а не требование печатать математическое решение вместо фото.

`fix_free_response_scoring --exam-version-id ID` показывает типы с
`manual_check`, которым ошибочно задано другое оценивание. `--apply` исправляет
типы только в неопубликованном черновике. Команда не меняет автоматически
переопределения старых задач и назначений; их следует проверять отдельно.

## Границы текущего этапа

Реализована самооценка владельцем работы. Значения источника `teacher` и `ai`
зарезервированы в модели, но интерфейса проверки репетитором, доступа к чужим
работам и подключения нейросети на этом этапе нет. Такие оценки нельзя
выставить, передав источник из браузера: сервер сохраняет только `self`.

Старый коммит `d708d26` и его ветка не объединялись с main. Полезные части
импорта, текстового ввода и обработки непроверенных ответов адаптированы
к актуальному решателю без восстановления удалённой старой страницы тренировки.
